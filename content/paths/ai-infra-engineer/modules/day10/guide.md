# Day 10 · 平台化 + 端到端实战 + 面试复盘

## 10.1 从「运维一个服务」到「运营一个 MaaS 平台」

你要管的不是单个 vLLM，而是**多模型、多租户、多规格**的平台。平台需要的能力：

- **模型管理**：模型仓库（HF / 内部）、版本化、格式转换、上线/下线。
- **多租户**：租户隔离（MIG/独立池/命名空间）、配额、限流、计费。
- **推理服务编排**：KServe 或自研 PaaS，把 vLLM/SGLang/TGI 封装成统一 OpenAI 接口。
- **路由与发现**：模型名 → 后端池。
- **灰度发布**：模型版本 A/B、金丝雀、按用户灰度。
- **可观测与审计**：全链路 trace（请求→网关→引擎→GPU）、审计日志、成本报表。
- **安全合规**：API 鉴权、模型供应链安全、prompt 注入防护、数据隔离。

## 10.2 参考架构（面试可画）

```
用户 → API Gateway（鉴权/限流/路由/计费）
        ↓
     模型路由层（模型名 → 后端池）
        ↓
    推理服务池（vLLM/SGLang/TGI，多副本）
        ↓
   K8s + Volcano（GPU 调度）+ Karpenter（节点弹性）
        ↓
   GPU 集群（DCGM 监控 + FinOps 计量）
```

## 10.3 端到端实战：搭一个最小 MaaS 平台

串起前 9 天所有知识：

```
API Gateway(APISIX 限流+路由+SSE)
  → vLLM 多副本(K8s GPU)
  → DCGM + Prometheus + Grafana(双层监控)
  → KEDA(排队深度伸缩)
  → 语义缓存层(Redis+向量)
```

**跑通标准**：能对着这张图，把一个请求从「进网关 → 路由到模型 → GPU 推理 → 流式返回 → 指标采集 → 超载自动伸缩」完整讲一遍，并现场演示限流、监控、伸缩。

## 10.4 面试复盘：10 道必背题 + 3 道手撕题

### 10 道必背（答案见《hands_on》文档 Part B）

1. LLM 推理 vs 传统服务的本质区别？
2. Prefill 和 Decode 吃什么资源？
3. Continuous Batching 和 PagedAttention 解决什么？
4. TTFT 和 TPOT 怎么优化？
5. 70B 模型两卡怎么部署？
6. GPU 利用率 100% 就高效吗？
7. 推理服务扩容为什么慢？怎么优化？
8. 怎么给推理平台做监控告警？
9. 高并发怎么保护推理服务？
10. 传统运维转 AI Infra 的优势？

### 3 道手撕（面试可能现场问，提前想好）

1. **「TTFT P99 从 1s 飙到 8s，怎么排查？」**
   → 分层定位：排队深度 → 显存水位 → 长 prompt 抢占 → 算力 vs 带宽瓶颈 → 硬件问题。

2. **「生成到一半断了，怎么查？」**
   → 优先怀疑网关超时（SSE 长连接被掐）→ 显存 OOM（KV Cache 打满）→ LB 空闲回收长连接。

3. **「要上新模型，怎么规划部署？」**
   → 算权重显存 → 定量化和 TP → 估 KV Cache → 压测定并发 → 配监控 → 灰度上线。
