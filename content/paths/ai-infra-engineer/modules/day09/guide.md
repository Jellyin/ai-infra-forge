# Day 9 · 弹性伸缩与 FinOps

## 9.1 弹性伸缩的难点：冷启动

**问题**：传统服务扩容秒级（拉镜像起进程），LLM 扩容要先加载几十 GB 权重到显存，**分钟级**。

```bash
# 实测冷启动耗时
kubectl scale deployment vllm --replicas=0
time kubectl scale deployment vllm --replicas=1
# 观察：这个时间 = 拉镜像 + 加载权重到显存
```

**优化手段**（面试必考）：
1. **模型预加载池 / 热备**：预起空转副本，扩容直接切流量（用显存换时间）。
2. **权重预热**：镜像预置权重，或用 P2P 分发（Dragonfly/Kraken）并行拉取。
3. **保持最小副本数**：scale 到 0 有冷启动惩罚，低谷也留 1 副本。

## 9.2 伸缩维度与工具

| 维度 | 工具 | 触发指标 |
|------|------|---------|
| Pod 水平伸缩 | KEDA / HPA + custom metrics | **排队深度**、请求速率、GPU 利用率 |
| 节点伸缩 | Karpenter / Cluster Autoscaler | 待调度 GPU Pod 数 |
| 模型多副本 | 多 Deployment | 租户/模型隔离 |

**关键差异**：传统 HPA 看 CPU，LLM 要看**排队深度**（`num_requests_waiting`），因为显存打满时 CPU 可能还很空闲。KEDA 支持从 Prometheus 自定义指标伸缩。

## 9.3 FinOps：成本是 MaaS 的核心 KPI

**认知转变**：一块 H100 月租上万，利用率 30% 和 70% 差一倍成本。FinOps 从「锦上添花」变成「核心 KPI」。

### 成本优化手段清单（面试能罗列）

1. **提升 GPU 利用率**：连续批处理、多租户共享、混部（训练夜间 + 推理白天）。
2. **Spot / 抢占实例**：离线批处理用 spot，在线推理用按需。
3. **语义缓存 + 前缀缓存**：命中缓存 = 白省算力。
4. **量化**：INT4/FP8 让同样的卡服务更多并发。
5. **弹性伸缩**：按需扩缩，避免空转。
6. **MIG 切分**：小模型用 MIG 分片，避免独占整卡浪费。

### 计量计费（MaaS 产品化必备）

- 计费维度：按 **token 数**（最细）、按 **GPU 卡时**（最粗）、按 **并发数**。
- 成本分摊：把 GPU 成本按租户/模型/部门归集。
- 监控指标：`DCGM_FI_DEV_GPU_UTIL` 聚合 → 利用率报表 → 成本报表。
