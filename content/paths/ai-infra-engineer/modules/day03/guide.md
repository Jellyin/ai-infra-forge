# Day 3 · GPU 硬件与显存

## 3.1 从「CPU 运维」到「GPU 运维」

传统运维你熟悉 CPU 的核、频率、缓存；GPU 要补的是完全不同的几个概念。**不需要学 CUDA 编程**，只需要理解资源特性。

### GPU 的两个「引擎」

- **算力（FLOPS）**：浮点运算能力，Prefill 阶段吃这个。
- **显存带宽（HBM bandwidth）**：显存读写的速度，Decode 阶段吃这个。

关键认知：**GPU 利用率 100% ≠ 高效**。Decode 阶段是内存密集，GPU 可能「算得很快但大部分时间在等显存搬运数据」。这就是为什么 Day 1 强调区分 Prefill/Decode。

### 显存层级

```
HBM（高带宽显存，几十GB，快）→ 主存（几百GB，慢一个数量级）→ 磁盘（最慢）
```

- 模型权重常驻 HBM。放不下 → **CPU Offload**（把部分层放主存），能用但慢 10 倍+。
- 所以「显存大小」直接决定「能装多大模型 + 留多少 KV Cache 空间」。

### 互联：NVLink 与 InfiniBand

多卡并行时，卡之间要高速通信：

- **NVLink / NVSwitch**：机内互联，带宽极高（900GB/s 级别）。单机 8 卡通常全互联。**张量并行（TP）必须在 NVLink 上做**，否则通信开销吃掉收益。
- **InfiniBand / RoCE（RDMA）**：跨机互联。多机分布式推理/训练依赖它。

### 卡的型号（2026 常见）

| 卡 | 显存 | 定位 |
|----|------|------|
| A100 | 40/80GB | 上代主力 |
| H100/H200 | 80/141GB | 当前主力，FP8 原生支持 |
| L40S | 48GB | 性价比，推理友好 |
| 4090/5090 | 24/32GB | 消费卡，缺 NVLink 和 ECC |

## 3.2 GPU 虚拟化：MIG 与 MPS

MaaS 平台要服务多租户，一块大卡怎么分给多个用户？

- **MIG（Multi-Instance GPU）**：硬件级切分，把一块 A100/H100 切成多个独立的小 GPU（如 7 个 1G.10GB），**硬隔离**，适合多租户、小模型场景。代价是切了之后不能拼回去跑大模型。
- **MPS（Multi-Process Service）**：多进程共享一块卡，**软共享**，提高利用率但无硬隔离（一个进程 OOM 可能影响其他）。
- **vGPU**：虚拟化 GPU，云厂商用得多。

**面试答案**：租户隔离选 MIG（硬隔离、安全），利用率优先选 MPS/共享池，具体看平台定位是「卖卡」还是「卖 tokens」。

## 3.3 显存预算：能装多大模型？（要会算）

这是面试必考的「算账题」。公式：

```
权重显存 = 参数量 × 精度字节数

FP16/BF16 = 2 bytes/参数
FP8       = 1 byte/参数
INT4      = 0.5 byte/参数
```

| 模型规模 | FP16 | FP8 | INT4 |
|----------|------|-----|------|
| 7B | 14GB | 7GB | 3.5GB |
| 13B | 26GB | 13GB | 6.5GB |
| 70B | 140GB | 70GB | 35GB |
| 405B | 810GB | 405GB | 202GB |

**再加上 KV Cache 显存**（并发越大、序列越长越重要）：

```
每 token KV ≈ 2 × 层数 × KV头数 × 头维度 × 精度字节数

例：Llama-70B（80层、8 KV头、head_dim=128、FP16）
每 token ≈ 2 × 80 × 8 × 128 × 2 = 327,680 bytes ≈ 0.31MB
1M token 上下文 ≈ 310GB  ← 这就是长上下文显存爆炸的来源
```

**实战决策逻辑**：
1. 先算权重显存 → 确定量化等级和 TP 切分。
2. 再算 KV Cache 需求 → 确定 `--gpu-memory-utilization` 和 `--max-num-seqs`。
3. 两者相加不超过显存上限，留 10% 余量防 OOM。

## 3.4 今日作业

用上面的公式，算三个题（面试原题）：
1. 一个 70B 模型 FP16，两块 A100-80G，能部署吗？KV Cache 能留多少？
2. 一个 13B 模型 INT4，一块 24GB 的 4090，能部署吗？
3. 一个 7B 模型，要支持 64 并发、单请求 4K token 上下文，KV Cache 需要多少显存？（提示：7B 级 MHA 模型每 token KV ≈ 0.5MB；用 Day 1 的公式算）
