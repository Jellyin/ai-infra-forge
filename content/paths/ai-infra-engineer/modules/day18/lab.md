## 第一部分 · MFU 手算（三道白板题，先自己算）

**题 1**：8×A100（312 TFLOPS/卡）训 7B，实测 9000 tok/s。MFU？

<details><summary>对照</summary>

7B×6 = 42 GFLOPs/token；9000×42G = 378 TFLOPS 实际；理论 312T×8 = 2496 TFLOPS → **MFU ≈ 15%**。不健康！该查：通信退化（Socket？）、数据饿（锯齿？）、TP/PP 组合气泡。
</details>

**题 2**：同集群改好数据管道后 25000 tok/s。MFU？

<details><summary>对照</summary>

25000×42G = 1050 TFLOPS → MFU ≈ **42%**——单机健康区间（40-60%）。从 15%→42% 就是「数据管道优化」的价值量化（这个数字面试讲出来就是实践证据）。
</details>

**题 3**：512×H100（990 TFLOPS/卡）训 LLaMA-65B（65×6=390 GFLOPs/token）。工单里写「实测 8500 tok/s」。算 MFU 前先问什么？

<details><summary>对照</summary>

**先问口径**：8500 是「每卡吞吐」还是「集群总吞吐」？——MFU 的分子分母必须同口径（每卡吞吐 / 每卡算力，或总量 / 总算力）。

- 若是**集群总吞吐** 8500 tok/s：总计算量 = 8500×390G ≈ 3.3 PFLOPS；总算力 = 512×990T ≈ 507 PFLOPS → **MFU ≈ 0.65%**——病入膏肓（几乎肯定哪里配置错了，比如实际只有几卡在干活）
- 若是**每卡吞吐** 8500 tok/s：每卡算力需求 = 8500×390G/990T ≈ **335%**——物理上不可能（超过 100% 上限），说明口径本身报错了

**教训**：MFU 题第一步永远是对口径。两个口径下这题一个「低得离谱」一个「高得离谱」——正是异常信号逼你回头质疑输入。
</details>

## 第二部分 · loss 曲线诊断（三张图，形态→结论）

**图 A**：`2.41 → 2.39 → 2.87(尖) → 2.40 → 2.41 → 2.88(尖) → 2.39`（周期性尖峰）

<details><summary>对照</summary>

**周期性 loss spike** —— 每隔 N 步撞到同一批脏数据（数据顺序固定）。定位：spike step % 周期 → dump 对应 batch → 清洗或剔除该 shard。
</details>

**图 B**：`1.8 平滑降至 1.1，此后 200 步抬到 1.4 走平`

<details><summary>对照</summary>

**拐头走平**：三嫌疑——过拟合（对照 eval：eval loss 若同期上翘即确诊）、从坏 checkpoint 恢复、数据分布变化（新数据源混入）。优先对照 held-out 曲线分叉。
</details>

**图 C**：`2.4 → 2.4 → 2.4 完全平线 500 步`

<details><summary>对照</summary>

**不动**：lr 配错（0 或过小）/ 数据格式错（没进 chat template）/ DDP 没包对梯度没同步（各卡各学各的随机噪声互抵）。三查：lr 打印、首条样本打印、梯度 norm 打印。
</details>
