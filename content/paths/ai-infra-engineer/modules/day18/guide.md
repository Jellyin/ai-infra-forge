# Day 18 · 训练可观测

> 目标：MFU/loss 曲线诊断/DCGM 训练视角

## 训练健康的三层指标（对照你熟悉的推理双层）

| 层 | 推理侧对应 | 训练侧指标 |
|----|-----------|-----------|
| 硬件 | DCGM（利用率/温度/XID） | 同一套 + **训练特有：SM 利用率的「锯齿/满载」形态** |
| 服务 | TTFT/吞吐/排队 | **MFU + 吞吐（tok/s）+ 步时（step time）** |
| 业务 | 正确率/成本 | **loss 曲线 + 评测分** |

## MFU——训练侧的黄金指标（必考）

**MFU（Model FLOPs Utilization）= 实际吞吐 / 理论算力上限**

```
7B 模型 × 6 FLOPs/参数/token = 42 GFLOPs/token
8×A100（312 TFLOPS×8）× MFU = 实际 tok/s
例：实测 8000 tok/s → MFU = 8000×42G/(312T×8) = 336/2496 ≈ **13.5%**（不健康——该查通信/数据/气泡）
```

**量级感（面试必备）**：单机 MFU 40-60% 健康；千卡集群掉到 30% 算正常（通信占比变大）——**MFU 是平台效率的北极星**，低于 30% 该查（通信退化/数据饿/气泡）。

## loss 曲线诊断——训练的「心电图」

| 形态 | 诊断 |
|------|------|
| 平滑下降 | 健康 |
| **锯齿/爆炸尖峰** | loss spike：数据有脏样本/ lr 太大 / 梯度异常——查 spike 对应的 batch |
| 降后突然抬升平台 | **坏了**：节点故障后从坏 checkpoint 恢复 / 数据分布变化 / 过拟合（对照评测集） |
| 完全不动 | lr 配错 / 数据格式错 / 梯度没同步（DDP 没包对） |

**loss spike 排障**（大厂真实痛点）：定位 spike step → dump 那个 batch 的样本 → 通常发现脏数据（乱码/超长/重复）。平台侧防线：**数据清洗的 pipeline 校验** + spike 自动回滚到前 checkpoint 重跑。

## DCGM 的训练特有读法

- SM 利用率**满载平线** = 计算受限（健康）；**锯齿** = 数据/通信受限（回 day14/12）
- 训练中 XID 48（ECC 不可纠错）/63（row remapping）高发——**训练比推理更易触发**（长时间满载压力大）
- 功耗墙：持续 boost 后降频 → step time 突然变慢但 MFU 计算不出原因时，先查温度
