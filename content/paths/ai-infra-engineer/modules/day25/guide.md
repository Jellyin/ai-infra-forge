# Day 25 · 容量规划与采购决策

> 目标：从利用率到采购单——把运维经验变成 CFO 听得懂的语言

## 容量水位模型（运维→平台的最后一块拼图）

```
当前利用率 → 增长预测 → 缺口时刻 → 到货周期 → 下单时点
   (监控)     (业务输入)   (外推)     (供应链)    (决策)
```

**水位线四档**（推理服务的经典模型）：
- 利用率 < 60%：健康（留峰值余量）
- 60-80%：黄色——启动容量评估（下次大促/新模型上线前）
- \>80%：红色——排队/SLO 恶化已在发生
- \>95% 持续：事故级——限流保命优先

**训练侧的容量单位不同**：不是 QPS 是「**卡时需求 ÷ 供给**」。算法团队的 roadmap（下季度要训几个模型、各多少卡天）就是需求侧输入——**容量规划=把 roadmap 翻译成采购单**，这是平台团队对接 CFO 的正规姿势。

## 峰值 vs 均值——采购账的经典分歧

- 均值利用率 40% 但**峰值 92%**：买不买？
- CFO 看均值（「你们一半卡闲着」），用户看峰值（「高峰排队」）
- **正确姿势**：P95/P99 水位 + 削峰手段的成本对比——「为 P99 的 8% 时间买整机 vs 上混部/弹性，哪个便宜」

**混部（错峰填谷）**——训练与推理的昼夜互补：
```
白天：推理服务满载（用户在线）｜训练任务低峰
夜间：推理空闲              ｜训练批量满跑（离线 SFT/蒸馏）
```
混部不是「往推理节点塞训练任务」那么简单（Day 19 的网络互扰/抢占风险），成熟做法是**分时调度 + 优先级反转**（推理永远抢占训练）——白天训练让路，夜间训练吃满。**这项能把集群有效利用率从 40% 拉到 65%+**，是采购论证里最值钱的一行。

## 采购 ROI 计算（一页纸论证的骨架）

```
1. 缺口：P95 排队 X 卡时/月 × $单价 = 用户体验损失（量化）
2. 方案 A 买卡：$N 资本支出 + 电力/机柜 + 折旧 3 年 → 月摊 $M
3. 方案 B 优化（混部/调度/量化）：
   - 混部预期 +25% 有效利用率 → 等效省 X' 卡时/月
   - 工程投入 $K 一次性
4. 推荐：B 先行（周期短见效快），A 按 6 个月后到货周期现在下单
```

**面试金句**：容量规划的本质是**用数据把「感觉缺卡」变成「缺多少卡、什么时候缺、买 vs 优化差多少钱」**——运维出身的人做这个有天然优势（监控数据就是你的母语）。
