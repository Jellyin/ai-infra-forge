# 🧪 动手实验 · Day 24

> **目标**：三道多模态容量题（纸上）——把「图像等效 token」的换算练成条件反射。

## 三道题（先自己算）

**题 1**：VLM 服务（LLM 上下文 4K + 单图 768×768、patch 16），每 token KV 0.3MB，KV 池 12GB。单并发消耗多少？能撑几并发？

<details><summary>对照</summary>

视觉 token = 768²/16² = 48² = 2304 ≈ 2.3K；总 4K+2.3K = 6.3K token × 0.3MB ≈ **1.9GB/请求** → 12GB 池 ≈ **6 并发**。
</details>

**题 2**：用户传 4096×4096 原图（无闸门）。等效多少 KV token？几并发就打爆 12GB 池？

<details><summary>对照</summary>

4096²/16² = 256² = **65,536 token（65K！）** × 0.3MB ≈ 20GB——**一张图就打爆整个池**。结论：多模态网关必须做图像分辨率硬限（如 1024² 上限），这就是「图像闸门」的量化依据。
</details>

**题 3**：容量规划——图片问答服务日均 100 万次请求、平均 2 图/请求（1024²）。月 token 等效吞吐是多少量级？对预算意味着什么？

<details><summary>对照</summary>

100 万 × 2 × 4K = 80 亿 token/日 ≈ 月 2400 亿等效 token。与纯文本服务比：同样 QPS 下多模态的 token 计费/容量要按「图片数 × 等效」预乘——**预算模型必须含图像转换率**（avg 图片数/请求），这是多模态平台计费模块的核心字段。
</details>
