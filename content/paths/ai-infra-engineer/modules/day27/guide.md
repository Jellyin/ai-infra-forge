# Day 27 · 毕业项目 II——关键路径实现

> 目标：把方案的核心链路做出来——不是全做，是**关键路径**（能证明平台闭环的最短链路）。

## 实现范围（刻意最小化）

方案的 80% 用文字论证，**只实现这一条链**：

```
提交微调任务（CLI）→ 队列排队 → 训练执行（含 checkpoint）→ 评测红线 → 合并 → 部署到 vLLM → 网关限流 → 对比验收
```

这条链覆盖：调度/训练/容错/评测/部署/网关——**每一环都是 30 天里学过的组件拼装**。复用清单：

| 环节 | 复用哪天的产出 |
|------|--------------|
| 训练脚本 | Day 13/15 的 lora_sft.py + ckpt_resume.py |
| 评测红线 | Day 17 的 eval.py + gate 检查 |
| 合并与上线 | Day 17 的 merge + Day 7 的 vllm serve |
| 网关 | Day 7 的 APISIX 配置（限并发+超时） |
| 流水线串联 | Day 20 的 run_all.sh |

**新增要写的只有**：一个 60 行的「任务提交 CLI」（把上述组件按队列串联+状态记录）——这就是你 capstone 的「自研部分」。

## 交付物清单

1. `submit.sh`/`main.py`：一条命令从提交到验收
2. `README.md`：项目总览（架构图 + 怎么跑 + 关键数字）
3. `DECISIONS.md`：决策日志——**每个技术选型一行「为什么+放弃了什么」**（面试官最爱看这个）
4. 运行证据：一次完整跑通的日志/截图（或纸上档的推演记录）

## 踩坑记录（等同交付物）

实现中必然踩坑（环境/依赖/格式）。**每踩一个记一行**：症状→定位→修复→对应哪天的知识。这份清单就是你的「实战经验」素材库——面试讲排障全靠它。

## 纸上档

写「影子实现」：给关键路径的每一环写输入/输出/接口契约（如 CLI 的参数表、队列状态机、各组件的调用时序图）。深度要求：**别人拿着你的影子实现文档能直接开工**——这就是设计能力的证明。

---

**验收自问**：我的链路里，评测红线是不是**自动拦截**的（不是人工看）？checkpoint 是不是**真存真恢复**的？如果这两个是 mock 的，链路就没闭环——回去补这两处，其他都可以假。
