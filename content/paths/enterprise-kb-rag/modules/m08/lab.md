# 🧪 动手实验 · 里程碑 8

> **本里程碑的交付物**：① 可运行的混合检索模块（BM25 + 向量 + RRF）② reranker 延迟预算与实测表 ③ 领域词典文件 ④ 每次改动的评测对比记录。
> **验收标准**：同事拿着你的评测报告能复现每一个结论——每条「收益」都对应 before/after 两个数字，且延迟增量在预算之内。
>
> 三档任选：**档位 A 真实项目**（有真实语料与黄金集）／**档位 B 本地练习**（docker 起向量库 + 本地 BM25 做对比）／**档位 C 纸上评审**（30 分钟，纯判断力训练）。

---

## 档位 A · 真实项目（推荐）

### 1. 先建最小黄金集，再写代码

没有黄金集，本模块的一切改动都无法验收。先构造 50 题：

| 题型 | 数量 | 示例 | 用途 |
|---|---|---|---|
| 精确符号题 | 15 | 「错误码 `0xE003`」 | 验证 BM25 的价值 |
| 概念/口语题 | 15 | 「休假怎么请」 | 验证向量的价值 |
| 缩写/内部术语题 | 10 | 「AK 泄露怎么处理」 | 验证领域词典的价值 |
| 混合题（带编号又口语） | 10 | 「上次 M4 定的那个超时」 | 验证融合与重排的价值 |

每题标注**正确 chunk 的 id**（不只是「哪个文档」），否则 recall@k 算不出来。

### 2. 分别量两路的独立表现

先把 BM25 与向量**各自**跑一遍黄金集，记录 recall@10 与 precision@5。这一步是为了确认「混合」是否真的有收益，而不是默认它一定好。

| 检索器 | recall@10 | precision@5 | 哪类题强 / 哪类题弱 |
|---|---|---|---|
| 纯 BM25 | | | |
| 纯向量 | | | |
| RRF 融合 | | | |

### 3. 实现 RRF 融合并验证

用 guide 里的 `rrf_fuse` 骨架，两路各取 top-50 融合，再取 top-10。注意两点：两路**并行**发出；`rank` 从 1 开始。

**必做验证**：故意把 k 从 60 改成 10 与 100，看排名变化——理解 k 的作用，但**不要**因此去「调优 k」到最好看的数值（那是在黄金集上过拟合）。

### 4. reranker：定预算，再实测

先按 guide 的延迟表定出 reranker 的预算（如 p95 ≤ 150ms），再测实际值：

```text
记录四项：候选数 k、top_n、batch_size、实际 p95 延迟。
再记录：开 reranker 前后同一黄金集的 context precision。
```

**上线判据**（写进报告）：precision 提升达到你设定的门槛（如 +10%）**且**延迟仍落在端到端预算内，二者缺一不上。

### 5. 领域词典

从语料里抽出内部缩写/产品名，写成 `domain_terms.yaml`，**只在索引期扩展**，重跑黄金集，记录 recall 增量。若某条别名的加入让精确符号题反而变差，说明扩展过宽，删掉它。

## 档位 B · 本地练习（无真实语料，照样能练手感）

用公开语料 + 本地组件搭一套**同构**混合检索，把「对比」这件事跑通：

```bash
# 1. 起一个本地向量库（Qdrant，REST 在 6333）
docker run -d --name qdrant -p 6333:6333 \
  -v "$(pwd)/qdrant_storage:/qdrant/storage" qdrant/qdrant

# 2. 备选：用 pgvector 的全文检索（ts_rank）当 BM25 一路
docker run -d --name pgv -e POSTGRES_PASSWORD=pg -p 5432:5432 pgvector/pgvector:pg16

# 3. 装本地 BM25 与交叉编码器（小模型无 GPU 也能跑）
pip install rank_bm25 sentence-transformers
```

本地 BM25 用 `rank_bm25.BM25Okapi`，对同一批语料跑「纯 BM25 / 纯向量 / RRF」，自己造 10 题（3 题精确符号、3 题概念、2 题缩写、2 题混合），**手动**标注正确 chunk。

> 这一档的价值：练的是「造对照实验」的手感——把两路的 recall 摆在同一张表里，而不是练某个库的 API。

## 档位 C · 纸上评审（30 分钟）

下面是一组查询与两路的 top-3 召回结果（`✓` = 正确 chunk）。逐题判断：**该以哪一路为主？融合够不够？要不要上 reranker？**

| # | 查询 | BM25 top-3 | 向量 top-3 | 你的判断 |
|---|---|---|---|---|
| 1 | 错误码 `0xE003` 的处置流程 | `✓ A` `B` `C` | `D` `E` `F` | |
| 2 | 年假怎么请、要几天 | `G` `H` `✓ I` | `✓ I` `J` `K` | |
| 3 | AK 泄露应急步骤 | `L` `M` `N` | `O` `P` `Q` | |
| 4 | M4 评审定的超时是多少 | `✓ R` `S` `T` | `U` `V` `W` | |

<details><summary>对照答案（先写完再看）</summary>

1. **以 BM25 为主**：精确错误码，向量分不清 `0xE003/0xE004`。融合后正确项仍应在首位；不需要 reranker。
2. **以向量为主**：口语与规范化文本的语义对齐，BM25 把正确项排到了第 3。融合能把正确项顶上来。
3. **两路都弱**：正确项两路都没出现——这是**领域词典缺失**（AK 没被识别为 Access Key），先去修词典，再谈融合与重排。
4. **以 BM25 为主**：M4 是内部编号，通用向量不认识。若融合后正确项没进 top-8，才轮到 reranker。

</details>
