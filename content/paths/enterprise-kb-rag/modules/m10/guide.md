# 里程碑 10 · 生成链路：上下文拼装与拒答

> **本里程碑的交付物**：① 可复用生成提示词模板 ② 上下文长度预算与截断策略 ③ 拒答判据 + 误拒率测量 ④ 会话记忆保留/丢弃清单 ⑤ 生成模型选型与成本估算。
> **验收标准**：把模板交给任何同事，他能独立填充证据、跑出「带引用或明确拒答」的回答；且你能指着日志说明某次拒答为什么发生、某次误拒代价多大。

## 10.1 检索对了，生成也能搞砸

检索给了 8 个相关块，模型照样能：编不存在的条款、把两个块缝在一起、用先验知识补数字、或无证据自顾自发挥。生成阶段的核心任务不是「说得更漂亮」，而是三件事：**只依据证据、每条结论可溯源、证据不足时敢拒答**。**提示词管生成期，代码管生成后**，缺一不可。

## 10.2 可复用的提示词模板（直接抄）

模板必须含四段：**角色 / 硬约束 / 证据 / 输出格式**：

```text
你是企业知识库的问答助手。你只能依据【证据】回答，不得使用自己的先验知识。

# 硬约束
1. 只能陈述【证据】中明确写出的事实。具体数值、日期、条款编号、人名，若证据里没有就不要出现。
2. 每条含事实的结论，句尾必须紧跟引用标记 [[n]]，n 是证据编号。
3. 若【证据】不足以回答、或证据互相矛盾且无法判定，必须只输出一行：
   INSUFFICIENT_EVIDENCE: <缺什么，一句话>
   不要编造，不要用「一般来说/通常」搪塞。
4. 不要复述规则。最多 5 个要点。

# 问题
{question}

# 证据
[1] 来源={title} | 章节={section} | 版本={version} | 锚点={anchor}
{chunk_text}

[2] ...

# 输出格式
- 第一行：一句话结论。
- 之后：<=5 条支撑要点，每条句尾带 [[n]]（可多条，如 [[1]][[3]]）。
- 无证据支撑的推理必须显式标注 (推断)。
```

**四段各司其职**：角色限定知识边界；硬约束把「不许编」变成可检查条款；证据提供唯一事实来源并携带引用元数据；输出格式让下游能**程序化解析**（`[[n]]` 与 `INSUFFICIENT_EVIDENCE` 都是可正则锚点）。**格式即接口**——格式模糊，校验无从谈起。要求「必须带引用」还会反过来抑制幻觉（模型收敛到只写证据支持的话），但引用真实性仍由生成后代码判定。

## 10.3 上下文拼装：顺序、去重、预算与截断

**去重与顺序**：同文档相邻块合并，`chunk_id` 与归一化文本双重去重（重叠切分必产生重复），否则既浪费预算又诱导重复引用；模型对上下文首尾更敏感、中间易忽略，所以**最相关 1–2 块放开头、次相关放结尾、弱相关沉中间**，而不是简单按分数降序。

**长度预算**先算总量再分配，不能写死「取 5 块」：

```
可用预算 = 上下文窗口 − 系统提示 − 问题 − 输出预留(>= 1k tokens) − 安全余量
逐块扣减，超出即停止纳入
```

**截断策略**（按序执行）：① 按（rerank 分数 × 时效）从低到高**整块丢弃，绝不从块中间截断**（会破坏引用锚点）；② 丢弃后**重编号**，保证 `[[n]]` 与最终证据集一致——否则生成 `[[7]]` 而证据只到 `[5]` 就是幻觉引用；③ 全程保留 `chunk_id ↔ 引用编号` 映射表，供生成后校验回溯。

## 10.4 拒答判据：什么时候必须说「不知道」

拒答不是「模型心情」，而是**可配置、可审计**的判据链，先严后宽、命中即拒：① 检索为空或 top-1 相似度 < τ₁；② rerank 后最高分 < τ₂（τ₂ > τ₁）；③ 证据与问题主题不一致（意图越界，分类器判定）；④ 证据间关键事实冲突且无法判定（拒答并提示冲突来源）。阈值必须由黄金集标定，不能拍脑袋——τ₁ 来自正负样本分布。

**两个必须测的数**：**漏拒率**（该拒没拒——编造答案，代价高）与**误拒率**（不该拒却拒——用户流失，代价也不低）。两者都进黄金集回归。**只调一个方向必然翻车**：阈值调高降漏拒却抬误拒。

## 10.5 流式与会话记忆：只留最小必要

**流式**改善首字体验，却与生成后校验冲突：token 已吐出才发现引用是假的。折中：**先判定拒答再开流**，或流式时延迟展示引用标记直至校验通过。

**会话记忆要极克制**——把「无限上下文」当方案是陷阱：成本线性涨、延迟涨、跑题概率涨。只留三类，其余全丢：**保留**当前轮证据集与引用映射、上一轮答案摘要、会话级过滤条件（如「只看本部门」）；**丢弃**历史轮原文块、中间推理与检索日志、闲聊。指代消解靠「上一轮摘要 + 当轮问题」足够；需要历史原文时**重新检索一次**更准也更便宜。

## 10.6 模型选型：质量 / 延迟 / 显存三角

自建栈下三者互相拉扯，**不能同时最优**。做法是用黄金集在 2–3 个候选（如 7B / 14B / 32B 量化档）各跑一遍，记录**引用正确率、误拒率、P95 延迟、显存占用**四列，**先按 SLO 硬门槛淘汰，再在通过者里挑性价比**；成本 = 单次 token 量 × 单价 × 日请求量，别忘算上检索与 rerank。

## 10.7 本里程碑的判断力

- 看到证据用 `"\n".join(chunks)`，先问：**去重了吗？预算算了吗？引用编号和最终证据集对齐了吗？**
- 看到「模型说不知道效果不好」，追问：**漏拒率还是误拒率？阈值谁标定？**
- 有人提议「把历史全塞进上下文」，反问：**要的是历史原文，还是重新检索？** 引用的真实性也不由模型自称，必须落到生成后校验。
