# 🧪 动手实验 · 里程碑 9

> **本里程碑的交付物**：① 可独立开关的查询改写模块 ② 多跳问题的拆解流程与逐跳评测记录 ③ 自然语言意图→元数据过滤条件映射表 ④ 每个增强的开关清单与归因记录（含负结论）。
> **验收标准**：同事能逐个开关每个增强模块、跑同一黄金集，并复现你给出的净影响结论——包括你判定「应该关掉」的那些增强。
>
> 三档任选：**档位 A 真实项目**（有真实会话与黄金集）／**档位 B 本地练习**（用规则或本地小模型搭改写与过滤，对着黄金集量收益）／**档位 C 纸上评审**（30 分钟，纯判断力训练）。

## 档位 A · 真实项目（推荐）

### 1. 先把会话日志分类，再谈改写

在本里程碑写代码前，先给最近的提问分类——**不同类别的改写策略完全不同**：

| 问题类别 | 数量占比 | 特征 | 对应增强 |
|---|---|---|---|
| 指代残缺 | | 「上次那个报错」「它怎么配」 | 会话上下文改写 |
| 纯口语 | | 「怎么弄」「咋回事」 | 去口语化 |
| 缩写/内部词 | | 「AK」「M4」 | 领域词典扩展 |
| 涉范围 | | 「我们部门的」「本项目的」 | 元数据过滤（身份推导） |
| 涉时间/版本 | | 「最新的」「去年的」 | temporal → 版本/时间字段 |
| 多跳 | | 「A 里定的，现在 B 里是多少」 | 多跳拆解 |

先算出各类占比，**据此决定先做哪个增强**——占比最高的那类才是收益最大处，别一上来就做最花哨的多跳。

### 2. 改写模块：先做最保守的版本

按 guide 的提示词骨架实现，输出 `rewritten / added_terms / dropped / confidence`。**第一版默认关闭**，仅记录它与原 query 的差异，先看它「想改什么」，不急着让它生效。

### 3. 归因矩阵：一次只开一个开关

```
黄金集（含各类别的题）→ 依次跑：
  基线（全关）
  +rewrite        → 记录 recall@10 / precision@5 的 delta
  +expand.synonyms（单独开，关 rewrite）
  +filter（身份范围）→ 记录 delta；另跑越权红队用例
  +temporal
  +multihop（仅对多跳题）
每一行都必须有 before/after 两组数字。
```

把结果填成一张矩阵——这就是你要交的「归因记录」。

### 4. 漂移量化

对每次改写记录 `1 - cosine(embed(原), embed(改写))`，设阈值标记「疑似漂移」进人工抽检。再统计 `added_terms` 中不在领域词典里的比例。

**必做负结论**：如果某增强的净收益为负（比如 precision 掉了、或漂移命中率过高），写下「默认关闭 + 原因」，这同样是合格交付物。

### 5. 多跳逐跳评测

挑 5 个真实多跳问题，手工写出 hop1/hop2 的期望子查询，分别量每跳的 recall。**不要只评最终答案**——逐跳才能看出是哪一跳在漏。

## 档位 B · 本地练习（无真实语料，照样练手感）

用本地组件搭一套**同构**的查询理解流水线：

```bash
# 沿用里程碑 8 起的本地向量库（如已在跑可跳过）
docker run -d --name qdrant -p 6333:6333 \
  -v "$(pwd)/qdrant_storage:/qdrant/storage" qdrant/qdrant

# 本地小模型做改写（无 GPU 也能跑）或先用规则版
pip install sentence-transformers

# 备选：把 pgvector 的 ts_rank 当检索后端，专门观察「去掉口语词」的收益
docker run -d --name pgv -e POSTGRES_PASSWORD=pg -p 5432:5432 pgvector/pgvector:pg16
```

自己造 12 个查询，覆盖档位 A 那张分类表；**手动**标注每句「理想改写」与应该在哪个 chunk 命中。然后：

1. 跑**规则版改写**（去停用词、同义词表替换），量 recall 变化；
2. 跑**模型版改写**（本地小模型按提示词骨架），对比规则版；
3. 分别开关元数据过滤（假装有 `dept`/`version` 字段），看「最新」「我们部门的」类题的正确率变化；
4. 记录每次改写的漂移值，画一张分布。

> 这一档的价值：练的是「把增强做成开关并量化」的手感，而不是练某个模型。

## 档位 C · 纸上评审（30 分钟）

给定一组查询，逐条判断：**要不要改写？要不要元数据过滤？是不是多跳？最该防的错误是什么？**

| # | 用户查询 | 改写？ | 过滤？ | 多跳？ | 最该防的错误 |
|---|---|---|---|---|---|
| 1 | 年假怎么请 | | | | |
| 2 | 上次那个超时到底改成多少了 | | | | |
| 3 | 我们部门今年的报销标准 | | | | |
| 4 | M4 评审定的阈值，最新配置里是多少 | | | | |
| 5 | AK 泄露多久内要上报 | | | | |

<details><summary>对照答案（先写完再看）</summary>

1. **不需要改写**（已是规范问法）；**不需要过滤**；单跳。防：过度改写把「年假」换成同义词反而引入噪声。
2. **需要改写**（补全指代，依赖会话上下文）；不改写就检索不动。**不改过滤**（此时还不知道实体，凭空的过滤值=编造）；单跳。防：模型在没有上下文时硬编一个实体（漂移）。
3. **不需改写**；**需要过滤**：`dept = 当前用户 dept`（**由身份推导，不是模型生成**）+ 时间窗「今年」。单跳。防：让模型或用户自定义 dept → 越权。
4. **需轻度改写**（补全「阈值」）；**需要过滤/排序**：`version = max`。**是多跳**：hop1 找 M4 定的值，hop2 查当前配置。防：把「最新」当普通词丢进检索，BM25 去匹配字面「最新」。
5. **需要扩展**（AK → Access Key，走领域词典）；**不需过滤**；单跳。防：词典扩展过宽把无关文档拉进来。

</details>

### 收束

无论哪一档，本里程碑结束前必须产出一行「可归因结论」——填不出来说明增强还没做成开关：

> 「在黄金集 ____ 题上，单独开启 ____（增强），recall@10 由 ____ 变为 ____，precision@5 由 ____ 变为 ____，漂移阈值命中率 ____，因此该增强默认 ____（开/关）。」
