# 里程碑 11 · 引用与溯源：把答案锚回原文

> **本里程碑的交付物**：① 引用锚点粒度决策 ② 生成后引用校验骨架 ③ 幻觉引用检测与统计 ④ 权限一致性保证 ⑤ 点击溯源前端契约 ⑥ 引用覆盖率回归指标。
> **验收标准**：点任意一条回答的每个引用都能跳到原文；校验脚本能列出「越界引用 / 不支持结论的引用 / 无引用断言」三类问题；越权提问既不返回、也不引用无权限内容。

## 11.1 没有引用的问答，在企业里不能用

引用是**把信任从模型转移到原文**：只要求用户点开看一眼，是否与结论一致他自己能判断。所以答错代价「中/高」的场景（见 m01），引用是**准入门槛**。但**有引用标记 ≠ 有依据**——模型能编一个不存在的编号，也能引用真实却不支持结论的块。故「给出引用」与「校验引用」是两件事。

## 11.2 引用锚点：选哪一级，以及为什么

锚点是「答案中一句话」指向「原文哪个位置」的坐标。越细精度越高，但越容易被文档更新打散：

| 粒度 | 定位精度 | 更新后稳定性 | 成本 | 适用 |
|---|---|---|---|---|
| **块**（chunk_id） | 中（整块） | 高（稳定 ID） | 低 | 通用默认，机器锚点 |
| **段**（标题路径） | 较高 | 中 | 中 | 结构化文档、人读定位 |
| **页**（页码） | 粗 | 低（PDF 重排即变） | 低 | 扫描件/PDF 必备 |
| **字符区间**（块内 offset） | 最高（可高亮） | 最低（重新解析就漂） | 高 | 需精确高亮 |

本项目选双锚点：机器侧「`chunk_id` + 块内字符区间」保证可回溯与高亮，人侧「标题路径 + 页码」保证用户能自己跳过去。**不要只选一个**——只用块用户不知跳哪，只用页码程序无法精确定位。字符区间必须**相对块**而非整篇文档，整篇 offset 会随解析器版本漂移。

## 11.3 提示词层的引用契约

在 m10 生成模板上追加可解析、可校验的契约段：

```text
# 引用格式契约
- 每个含事实的句子句尾必须带一个或多个 [[n]]，n ∈ {证据编号集合}。
- 严禁引用集合外的编号；严禁编造编号。
- 引用必须真正支持该句结论：不要为了「看起来有依据」而随意挂引用。
- 无证据支撑的推理句标注 (推断)，不挂引用。
- 只输出证据编号，不要输出 URL 或自定义格式。
```

提示词只做到「尽量守约」，**真正的保证在下一步**。

## 11.4 生成后校验：实现骨架

校验层是生成与展示之间的**必经闸门**（Python 伪代码）：

```python
def verify_answer(ans, evidence_map, authorized_ids):
    # evidence_map: {编号 -> chunk}，仅含权限过滤后的证据
    issues = []
    cites = extract_cites(ans)                    # 正则 \[\[(\d+)\]\]
    for n in cites:
        if n not in evidence_map:                 # 1) 越界引用
            issues.append(("nonexistent_block", n))
        elif evidence_map[n].id not in authorized_ids:    # 3) 权限一致性
            issues.append(("permission_leak", n))
    for sent, cs in split_sentences_with_cites(ans):      # 2) 逐句
        if not cs:
            if looks_factual(sent):               # 非寒暄、非纯推断句
                issues.append(("uncited_claim", sent))
        elif not any(supports(sent, evidence_map[n].text) for n in cs if n in evidence_map):
            issues.append(("unsupported_claim", sent, cs))
    return issues
```

**`supports(sent, chunk_text)` 三档实现**：① **词面重叠 + 数字/实体对齐**（结论里的数字、日期、编号能否在证据中找到；便宜，抓「数字幻觉」，抓不住改写）；② **NLI 蕴含小模型**（较准）；③ **LLM-as-judge**（最准但贵、有延迟，别放在线关键路径）。**推荐**：在线用 ① 拦硬伤，离线回归用 ②/③ 发现软性不支持。

**处理分层**：越界引用 → **直接拦截**（绝不展示）；不支持结论 → 降级为「无引用」并标注或触发重生成；无引用断言 → 视配置拦截或加警示标签。## 11.5 「幻觉引用」的两类检测

**① 引用了不存在的块**（`[[7]]` 而证据只到 `[5]`）：用「编号 ∈ evidence_map」的集合检查（骨架第 1 步）。**② 引用与结论不符**（块真实存在，但内容不支持该句）：用蕴含判定 / 词面+数字对齐（骨架第 2 步）。两类都做成**可统计指标**（每千次回答的幻觉引用条数）并进发布门禁；只查第一类不够，第二类更隐蔽、更像「真的」，危害更大。

## 11.6 权限过滤后的引用一致性

引用是**权限泄露的隐蔽通道**：即使正文合规，指向无权限文档的链接本身就是泄露。三道防线缺一不可：① **证据集即授权集**（进提示词的证据就是权限过滤后的集合，别先生成再过滤引用）；② **校验期复核**被引用块 ∈ 授权集合（骨架第 3 步）；③ **展示期再校验**：点击时按当前权限重新鉴权再决定是否返回原文，防「提问时有权、点击时无权」的漂移。

## 11.7 前端呈现：一次点击的契约

后端返回的每条引用是结构化对象，前端只负责渲染与跳转：

```json
{ "marker": 2, "doc_id": "hr-policy-2024", "title": "员工手册",
  "section": "3.2 年假", "page": 12, "chunk_id": "hr-policy-2024#c17",
  "char_range": [840, 1021] }
```

点击行为定义清楚：能定位到段落就高亮该段；PDF 跳到对应页并框选字符区间；源站可直达就给外链。**每加一个字段都要有消费者**——没人用的元数据只是负担。
## 11.8 引用覆盖率：把「有引用」变成回归指标

定义写死，否则各说各话：`引用覆盖率 = 带至少一个「有效引用」的结论句数 / 结论句总数`，其中「有效」= 通过 11.4 全部校验。与黄金集基线对比：**覆盖率下降即视为回归失败**，哪怕答案读起来更流畅。覆盖率要与**不支持率**一起看——覆盖率刷高不代表好，可能只是模型学会了到处挂引用。

## 11.9 本里程碑的判断力

- 引用只存了 URL/页码，追问：**程序怎么校验？文档更新后锚点还在吗？**
- 任何引用展示先问：**这个块，当前用户有权看吗？点击那一刻再查一遍了吗？**
