# 里程碑 2 · 知识建模：元数据、权限与切分粒度的前置决策

> **本里程碑的交付物**：① 文档类型→解析→切分映射表 ② 元数据字段表 ③ 权限模型（检索期过滤条件）④ 引用锚点方案 ⑤ 本项目第一份 ADR。
> **验收标准**：换个人接手，只看这五份文件就能说清「每个字段为什么存在、越权请求在哪一层被拦、答案里的引用能指回原文哪一级、过期文档怎么处理」。

## 2.1 三个决策，定错了后面每一步都在还债

三个决策必须在写接入管道前冻结成文档：

| 决策 | 选错的后果 | 什么时候无法回头 |
|---|---|---|
| 切分粒度 | 块太大→召回噪声、成本高；块太小→语义割裂、引用指不回 | 索引建完再改=全量重切重嵌 |
| 元数据字段 | 权限/时效无法过滤，只能事后打补丁 | 字段没进 payload，检索期就用不了 |
| 引用锚点 | 引用指向整篇文档，等于没引用 | 解析时没存锚点，事后补不回来 |

## 2.2 文档类型 → 解析方式 → 切分粒度

| 文档类型 | 解析方式 | 切分粒度 | 理由 |
|---|---|---|---|
| Markdown / HTML | 按标题层级 | **按标题块**（h2/h3） | 结构即语义边界，标题路径可作锚点 |
| 结构化 PDF | 布局解析取标题 | 节/子节，超长再切 | 页码+章节可作锚点 |
| 扫描件 PDF | OCR | 页内段落 | 无结构，只能靠 OCR 段落 |
| FAQ / 工单 | 按问答对 | **一问答一块** | 跨块会答非所问 |
| 表格 / Excel | 表头 + 行 | 表头随每个行块 | 缺表头的行块无法理解 |
| 代码库 | 按符号 | 一符号一块 | 函数边界即语义边界 |

**判据**：一个块=一个可独立回答的最小语义单元；超长块再按 `chunk_size`+`overlap` 二次切（经验值 500–800 token、overlap 10%–15%，随语料调）。

## 2.3 元数据字段表：每个字段都要能回答「检索期用不用它」

判据：**能在检索期变成过滤条件、或能变成引用展示的，才值得进 payload**。

| 字段 | 示例 | 检索期用途 |
|---|---|---|
| `doc_id` | `kb-0042` | 按文档聚合 / 删除传播 |
| `chunk_index` | `7` | 相邻块扩展、去重 |
| `source_uri` | `confluence://HR/page/123` | 引用链接 |
| `doc_type` | `policy` | 过滤（只要制度） |
| `department` | `hr` | **权限过滤** |
| `classification` | `internal` | **权限过滤** |
| `version` | `v3` | 取最新版 |
| `valid_from` / `valid_to` | 日期 | 过滤过期 |
| `anchor` | `{"page":4,"section":"3.2"}` | 引用展示 |
| `content_hash` | `sha256:...` | 增量判重（幂等） |

**为什么进 payload**：向量库只按自身载荷/标量字段过滤，只存关系库则检索期要额外查库拼 ID、无法与向量检索融合（Qdrant `payload_m`、Milvus 标量字段/分区键均要求权限字段在库内可过滤）。多值字段用**数组**而非逗号串，以便过滤器做 `any` 匹配。

## 2.4 权限模型：把「谁能看什么」翻译成过滤条件

权限必须在**检索期**挡掉越权文档；生成后再过滤时，越权内容已进模型上下文。

```
可访问集合 = { doc | doc.department ∈ user.departments
                    ∧ rank(doc.classification) ≤ user.clearance
                    ∧ now ∈ [doc.valid_from, doc.valid_to] }
```

同一模型，三种后端落地：

```json
// Qdrant：检索请求里带 filter
{"filter":{"must":[
    {"key":"department","match":{"any":["hr","legal"]}},
    {"key":"classification","match":{"any":["public","internal"]}}],
  "must_not":[{"key":"status","match":{"value":"archived"}}]}}
```

```python
# Milvus：标量字段布尔表达式（字段需建标量索引；以官方文档为准）
expr = 'department in ["hr","legal"] and classification in ["public","internal"] and status != "archived"'
```

```sql
-- pgvector + Postgres 行级安全（RLS）：权限下沉到数据库
ALTER TABLE chunks ENABLE ROW LEVEL SECURITY;
CREATE POLICY dept_scope ON chunks USING (
    department = current_setting('app.current_dept')
    AND classification = ANY(string_to_array(current_setting('app.clearances'), ',')));
```

**关键判断**：权限粒度必须细到**块级可过滤**（块继承文档权限字段）——若文档存在部分受限内容而权限只到文档级，就无法表达，这是最常见的越权漏洞来源。

## 2.5 引用锚点：答案要能指回原文的哪一级

锚点最细到哪一级，决定能否「一键跳回原文」：

| 目标 | 锚点粒度 | 需要的解析产物 |
|---|---|---|
| 一致性 / 合规（高代价） | **页码+段落**（PDF）或**标题路径** | 解析时记录每块的 page/section |
| 内部流程（中代价） | 章节 | 标题层级 |
| 自助问答（低代价） | 文档级 | 源 URI |

**判据**：锚点粒度 = 里程碑 1 的答错代价分级；高代价场景必须到「页/段」，这要求解析阶段就把锚点写进 payload。

## 2.6 版本与时效：过期文档不是删掉就完事

| 策略 | 做法 | 适用 |
|---|---|---|
| 只留最新 | 旧版打 `status=archived`，检索排除 | 制度/价格这类「旧版即错误」 |
| 全留但降权 | 旧版保留、检索降权 + 标版本 | 有历史比对需求 |
| 时效窗口 | `valid_to < now` 的块过滤掉 | 活动/临时政策 |

**默认不物理删除旧版**：审计回溯需要「当时依据的是哪一版」。默认软删除（`status`）+ 检索期过滤，物理删除只留给真正的主体删除请求，且要能传播到索引。

## 2.7 把它写成一份 ADR

```markdown
# ADR-001 知识建模三决策
## 状态
已接受 / 2026-01-01
## 背景
（一句话：为什么现在必须定，不定会怎样）
## 决策
1. 切分：Markdown 按 h2/h3；PDF 按节；超长二次切至 600 token
2. 元数据：doc_id / department / classification / valid_to / anchor / content_hash 进 payload
3. 权限：块级继承文档权限字段，检索期用 filter 表达
4. 引用锚点：PDF 到页+段，Markdown 到标题路径
## 后果
- 正面：权限与时效可在检索期过滤，引用可核验
- 负面：解析成本上升；payload 索引占额外存储
- 未决：多值权限数组字段的上限
```

## 2.8 本里程碑的判断力

- 有人问「块切多大」，先反问：**这块要能独立回答什么问题、引用要指到哪一级**。
- 看到权限方案，先问：**它是检索期过滤，还是生成后过滤**——后者意味着越权内容已进了模型上下文。
- 看到「文档级权限」，追问：**同一文档里有没有部分受限的内容**。
- 没写成 ADR 的决策等于没决策。
