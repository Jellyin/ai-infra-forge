# 🧪 动手实验 · 里程碑 1

> **本里程碑的交付物**：① 目标与范围一页纸 ② 语料盘点表 ③ 延迟/成本预算表 ④「本期不做」清单。
> **验收标准**：陌生同事读完这四份文件，能准确说出「给谁用、答错代价多大、多少毫秒内必须答完、本期不做什么」——不需要问你任何一个问题。
>
> 三档任选：**档位 A 真实项目**（手上有真实语料与真实提问方）／**档位 B 本地练习**（无真实语料，用公开文档造一份同构场景）／**档位 C 纸上评审**（30 分钟，纯判断力训练）。

---

## 档位 A · 真实项目（推荐：本路径的四个交付物都从这里来）

### 1. 先做访谈，再做表格（顺序不能反）

找 3 类各一位真实提问者，每人问三个问题并**逐字记录**（不要转述）：

```text
1. 你上一次在文档里找不到东西，是什么时候、要找什么？
2. 你找到之后，怎么判断它是对的/最新的？
3. 如果系统答错了，你会有什么损失？你怎么发现的？
```

**记录表**（这是后面所有设计的原料）：

| 提问者 | 角色 | 原话（逐字） | 问题类型（事实/流程/多跳） | 答错代价（低/中/高） | 现如今的替代做法 |
|---|---|---|---|---|---|
| | | | | | |

### 2. 语料盘点（半天，别跳）

```bash
# 先估规模，不要一开始就精确统计
du -sh /path/to/shared-drive 2>/dev/null
find /path/to/shared-drive -type f -name '*.pdf' | wc -l
find /path/to/shared-drive -type f \( -name '*.docx' -o -name '*.xlsx' \) | wc -l
```

**关键动作：随机抽 20 个文件打开看**，记录三类坑的命中情况：

| 抽检项 | 命中数 | 说明 |
|---|---|---|
| 扫描件（无文本层） | | 解析成本翻倍 |
| 章节结构混乱/无标题层级 | | 影响切分与引用锚点 |
| 涉及多部门权限 | | 影响权限模型设计 |

### 3. 写预算表并**反推**选型

```text
日活人数 × 人均提问次数 = 日请求量
日请求量 × 单次成本上限 ≤ 月度成本预算
```

把算出来的数字填进 guide 里的预算表；如果单次成本上限被压到很低，**这一条就要写进「选型约束」**（例如：必须先做缓存、上下文不能超过 N k）。

## 档位 B · 本地练习（无真实语料）

用公开语料造一个同构场景——比如把某个开源项目的官方文档（`docs/` 目录）当成「企业知识库」：

```bash
# 1. 取一份有层级、有表格、有多版本的文档集
git clone --depth=1 https://github.com/prometheus/prometheus /tmp/kb-corpus
find /tmp/kb-corpus/docs -type f -name '*.md' | wc -l

# 2. 盘点：规模、类型、更新频率（用 git log 代替「谁在维护」）
cd /tmp/kb-corpus
git log -1 --format='%ci %an' docs/ | head -1
find docs -name '*.md' | sed 's/.*\.//' | sort | uniq -c
```

然后**当作真实项目**做同样四件事：三类提问者（假装是「新用户/老用户/维护者」）、答错代价、预算表、不做清单。

> 这一档的价值：练习**用数字约束设计**的手感，而不是练工具。

## 档位 C · 纸上评审（30 分钟）

下面是一份**看起来很完整、实际无法验收**的立项文档节选，找出它的 6 个问题：

```text
项目目标：建设企业级知识库，实现智能问答，提升员工效率。
成功标准：
  1. 回答准确率 95% 以上
  2. 用户体验良好，响应快速
  3. 覆盖公司全部文档
技术方案：使用大模型 + 向量数据库，采用 RAG 架构。
范围：公司所有知识文档。
```

<details><summary>对照答案（先写完再看）</summary>

1. **「准确率 95%」无法验收**：谁测？测什么集合？什么算准确？没有黄金集就没有分母。正确写法是「黄金集 200 题中，事实类正确率 ≥ 85%」。
2. **「体验良好/响应快速」不可测量**：要换成 TTFT / P95 端到端的具体毫秒数，并**说明该数字的来源**（谁的场景、超过会怎样）。
3. **「覆盖公司全部文档」是范围炸弹**：与「本期不做」直接冲突；应改为可枚举的源清单 + 优先级。
4. **没有提问者画像**：不知道给谁用，就无法定答错代价，也无法定架构。
5. **技术方案先于目标**：直接写「大模型 + 向量库 + RAG」——没有先定 SLO 与代价分级，选型没有依据（且「向量库」在低代价场景可能完全不必要）。
6. **没有「本期不做」清单**，也没有负责人/时间点。

</details>

### 最后：把结论压成一页纸

无论哪一档，本里程碑结束前必须产出这段「一句话目标」——填不出来说明还没想清楚：

> 「为 **____（谁）** 解决 **____（哪类问题）**，答错代价为 **____（低/中/高）**，因此必须在 **____（延迟）** 内给出**带引用/可拒答**的回答，本期**不做 ____**。」
